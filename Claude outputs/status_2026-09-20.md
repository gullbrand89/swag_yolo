## Det som gick sönder-och-fixades i tänkandet

Tre gånger på två dagar har samma mönster återkommit: ett fält står platt oavsett vikt,
steg och storlek, och orsaken är att modellen måste **räkna** något (besök sedan nivån
sågs, antal nivåer, position i cykeln, position i ORDER-blocket). Varje gång har fixen
varit att ge räkningen som **input** (recur, visit, seg_pos) eller som **encoder-mål i
ett svep** (count), inte att träna hårdare. Se `cyc_diag`-docstringen och
kommentarerna vid `labels._canon`, `data.make_channels`, `model._seg_pos`.

## Kod som lades till

- `labels.py` — `to_tokens(..., start=)`: med start och P ≥ 3 ankras ORDER/DWELL
  FIXED vid fönstrets första besök i stället för lexikografiskt minsta rotation.
  Utan start: identiskt med förut (3000/3000). `canon_info` ger `anchored`.
- `all_emitters.py` — `_make_signal` → `(pri, start, aux)`; `label["start"]` per
  signal. Facitet är nu **per signal**, inte per emitter. Cyc-målet räknas med
  samma rotation som posten (verifierat 118 272/118 272 rent, 75 903/75 903 med
  bortfall).
- `data.py` — `label_to_tokens(label, i)`. Besökskanalen `visit` (`cfg.use_visit`,
  tak 64). Cyc-målet maskas bortom taket.
- `model.py` — `AuxHeads.cyc`, `AuxHeads.period` (`period_per_pulse`, röstning i
  `period_logits`). `_seg_pos`: token sedan senaste strukturtoken, embedding på
  avkodarens input (`cfg.use_seg_pos`). `_period_constraint` i `generate()`.
- `loss.py` — cyc som per-puls-huvud, period som eget vägt led (per puls eller poolat).
- `tools/cyc_diag.py` — per variant: cyc, cyc_shift, P_acc, order, order_rot,
  order|cyc. Skiljer "encodern bär inte informationen" från "avkodaren läser inte av".
- `tools/reeval.py` — `--period/--no-period`; formflaggor för alla nya fält.

**Obs:** `tools/baseline.py`, `show_failures.py`, `inspect_label.py` bygger facit
utan start → kanonisk rotation → ser ut som fel mot modellens ankrade utdata.

## Nästa

1. **Bortfall i ORDER.** Besökskanalen räknar *observerade* besök; ett tappat besök
   (stagger, dwell 1) förskjuter alla etiketter efter det. Encodern ser
   sammanslagningen (merge-huvudet 0,8) men måste ackumulera korrektionen — en
   räkning igen. Kandidat: låt `visit` räkna sammanslagna intervall som två besök
   när bin > pri_max-rymden (deterministiskt ur input, som `rl` gör med flaggor).
2. **Perioden** är taket för stagger (P_acc 0,635 rent, 0,475 vid bortfall).
   Per-puls-huvudet gav inget. Nästa idé: ett *jämförelsemål* — per puls "återkommer
   mitt mönster om k besök?" för k = 1..32, så att huvudet svarar på en lokal fråga
   i stället för att gissa ett globalt tal.
3. Punkterna från igår står kvar: RL med likelihood-belöning för bortfall, formatet
   per tillstånd, fler mätstorheter.

## Öppet (nytt)

- Facitet är per signal: `samples_per_emitter > 1` ger nu olika poster för samma
  emitter. Det är avsiktligt (posten beskriver signalen), men `verify.py` och
  `tests.py` antar per emitter på sina håll — de går igenom, men bara för att
  kontrollerna är rotationsinvarianta.
- `max_visit = 64` är ett tak som gör cyc-huvudet meningslöst för stagger med långa
  fönster. Höjs det måste cyc-målet (`visit mod P`) omprövas — det är räkning igen.
